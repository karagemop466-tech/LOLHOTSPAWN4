Methodology & sources

Every number on this site traces to a source listed below, fetched at a recorded time (shown on each match card and in data/raw/manifest.json in the repo). Values that cannot be confirmed from a verified source are left blank and flagged.

3. How a pick is generated

Tier 1 — Market line. An open per-match market prices both teams (currently only Polymarket has LoL match markets, e.g. Worlds 2026 and EMEA Masters). Probability for each team = the market mid exactly as reported (no adjustment, no blend). Pick = the higher side. If the market is exactly even, no pick is made and the match is noted.

Tier 2 — Derived estimate (our own line). No per-match market, but both teams have open tournament-futures markets in the same Kalshi/Polymarket event. We originate the line with the transparent ratio model p(A) = f(A) / (f(A) + f(B)) (f = futures mid). It is labeled "Derived (our line)" on every card, shown on the Flagged for Review page with both input markets linked, and marked low confidence. Remove it on the flagged page if you don't want model lines.

Tier 3 — Unresolved. No verified external market exists (typical for low-tier regional events). No probability, no pick. The match stays on the Flagged for Review page until a market appears; the 4-hour refresh picks it up automatically.

Pinnacle coverage is recorded as a badge (the match is line'd by a pro book) but never used numerically, because its public API exposes no prices. Hotspawn's own crowd percentages are never used for probabilities, per the project requirement.

4. Matching rules (Hotspawn fixture → market)

  • Team names: case/punctuation-insensitive; match on exact equality, containment (names ≥ 4 chars), stopword-stripped word-set equality ("esports", "team", …), or sequence ratio ≥ 0.86. Deliberately conservative — a near-miss degrades to "unresolved" rather than a wrong pick.
  • Time: the market's game start must be within 36 h of the Hotspawn start (same-day events always pass; event-level start falls back to 72 h).
  • Pinnacle coverage: teams match and start times within 24 h.
  • Multiple candidate markets: smallest time delta wins, volume breaks ties; the candidate is stored in the match's lines array for review.

5. Refresh & operations

  • Schedule: GitHub Actions workflow .github/workflows/refresh.yml runs every 4 hours (cron 0 */4 * * *) plus on manual dispatch. Within the required 4–8 h window.
  • Pipeline: collector/fetch_hotspawn.py → collector/fetch_odds.py → collector/build.py; each step validates schema, saves a snapshot to data/raw/ with URL, timestamp, and SHA-256 in data/raw/manifest.json, and logs an audit table.
  • Failure handling: if a source fetch fails, the previous snapshot is reused and marked stale; the site shows a STALE banner. The pipeline never fills missing values with invented data. If all odds sources fail, the dataset is still rebuilt from the last good snapshots (matches keep their prior lines, flagged stale).
  • Publishing: the workflow commits data/ back to the branch it runs on; GitHub Pages serves main, so the public site updates automatically. The full Polymarket events dump is kept as a workflow artifact (90-day retention) for deep audit; committed raw files are the normalized extracts.
  • Audit trail: every published number carries the fetch timestamp from the manifest; every match card links to the exact market page used.
